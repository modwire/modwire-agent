# GitHub workflow

1. Start with a clean local workspace and inspect existing changes before editing; preserve unrelated work.
2. Make changes only in the local workspace and keep them scoped to the request.
3. Before review, run the checks in the quality loop and state any known failures or unrun checks.
4. Keep commits intentional and focused. Before pushing a feature branch, squash its current work into one clear commit when that is the team's workflow.
5. Submit a pull request only after the intended QA checks pass. Do not change GitHub workflows unless a rollout explicitly calls for it.
6. After merge, clean up local and remote feature branches according to the team's repository policy.
